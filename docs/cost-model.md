# 成本模型与边界

本页给出可用于选择算法的工作量模型。这里的 O(·) 主要描述生成出的 PP3 程序执行多少次宏级/DSL 操作，不是对 Python 解释器耗时、内存字节数或 wall-clock 的承诺。

## 四种不同的成本

讨论 Toolkit 程序时要分开看：

1. **生成器运行时间**：Python 两遍调用生成函数、拼接字符串并格式化括号。它随生成源码大小、宏调用点数量和字符串操作增长。
2. **生成源码大小**：固定宏通常只展开一次，与运行时输入数值无关；若调用者在 Python 循环中展开 N 次，源码当然会随 N 增长。
3. **PP3 执行工作量**：标准操作/控制流在运行期间执行的次数。下表主要讨论这一层。
4. **宿主 Runtime 成本**：每次操作仍要由 PP3 Python Runtime 分派，间接寻址还会执行 Python 字典访问和整数运算。它取决于整数地址位数、哈希、字典状态、Python 版本及运行器实现。

因此，“固定条数的 PP3 模板”不自动等于机器上的常数时间；“O(n) 个 PP3 操作”也不等于只做 O(n) 个等成本 CPU 指令。

## 主要宏的工作量

以下以数值宏级循环轮数描述。固定深度寻址每条都有有限条 PP3 操作，但其 Python 整数地址和字典访问成本不是固定 CPU 时间。

| 操作 | PP3 执行工作量 | 为什么 |
| --- | --- | --- |
| read / constant / copy | 固定模板大小 | 固定深度路由；不按载荷枚举 |
| change | 固定模板大小 | 单次自增/自减和固定路由 |
| equal(a,b) | 固定数量的 DSL 控制步骤 | 用地址标记，不按 a 与 b 差值递减 |
| compare(a,b)，a=b | 固定级别的判等路径 | 判等命中后跳过竞速递减 |
| compare(a,b)，a!=b | O(min(a,b)+1) | 两份副本同步递减到至少一个为零 |
| add_into(dst,src) | O(src+1) | 每轮给目标加一、计数器减一 |
| subtract_from(dst,src) | O(src+1) | 前置条件 dst>=src，每轮减目标和副本计数 |
| multiply_by_ten(x) | O(x+1) | 将 x 次数的循环体各执行十次自增 |
| divmod_unsigned(n,d) | O(n+1) | 工作副本从 n 逐一递减，按 d 维护商余数 |
| print_unsigned_decimal(x) | 最坏随 x 数值线性增长 | 位权构造和逐位除法都基于重复减法 |
| NegativeArray.seek(i) | O(i+1) | 游标逐格向负方向移动 |
| RecordList/Chain append、pop、concat | 固定级别链操作 | 直接读写 head/tail/NEXT，不遍历已有链 |
| merge_sort，n 个节点 | O(n log n) 次链操作 + 比较成本 | 归并趟数对数级，每趟搬移每个节点常数次 |
| frame_program，长度 n | O(n) 次字符读取与处理 | 精确消费 n 个码点，每个执行一个静态 consume 片段 |
| dual_frame，长度 c、d | O(c+d) 次帧字符处理 + finish | 两段各读一次；执行主体依使用者生成的程序 |
| InstructionMachine 加载 m 条指令 | O(m) | 每条源码指令分配并追加一个节点 |
| InstructionMachine 执行 | 与客体实际执行指令数相关 | 循环跳转是局部引用操作，但客体循环可重复任意多次 |

加法、减法、比较、除法输入都是 PP3 槽值，不会在宏调用前由 Python 计算。表中的 n/a/x 是运行时自然数。

## 为什么判等快而比较仍可能慢

等值判定能把自然数 k+1 变为稀疏地址，使用 0/-1/-2 三种状态做局部标记。源码不包含从 0 数到 k 的循环。因此它对数值差值不敏感。

大小关系没有同样的已排序地址遍历能力。compare 先判等，然后对不等值做同步递减；例如比较 1 与 10^12，竞速阶段仍要走约 1 轮；比较 10^12 与 10^12+1 则需要约 10^12 轮。算法避免按最大值生成分支，却不是位复杂度比较器。

这一区别很重要：不能从 equal 的固定 DSL 路径，推导出排序、除法、十进制转换也都与值大小无关。

## 容器与算法规模

### 数组和记录

NegativeArray 每存一个元素使用一个动态负地址；Arena 的 width=W 记录每节点占 W+1 个地址，其中一个是零头。数组索引/记录引用以自然数槽和引用槽保存。Runtime 使用稀疏字典，不会因为地址为 -10^100 就预分配 10^100 个连续单元；但大整数键、哈希运算和历史访问留下的零值项仍然有宿主成本。

记录释放或把字段写零只改变逻辑状态，不保证 Python defaultdict 删除对应键。程序长时间触碰大量不同地址时，物理字典可能持续增长。

### 稳定归并排序

对 n 个节点，底层拆分/追加/拼接约 O(n log n) 次。每次键比较调用自然数 compare。若所有比较都为相等，equal 路径有固定控制流级别；若键不同，则比较工作与该对键的较小值有关。

简单的上界表述可写为 O(n log n * (M+1))，其中 M 是最大键；实际成本由每次比较的 min(left,right) 及相等快路共同决定。不能笼统写成仅 O(n log n) 的真实运行时间。

### 字符帧校验

每个字符都验证非负且不超过 255。超范围但非负的字符会走自然数比较；比较的小侧被 255 限制，因此额外递减轮数有固定上界，但不是一个只有单次字典访问的免费检查。负字符不属于 @input_as_char 的正常码点模型。

## 两遍生成的代价与确定性

compile_program 在生成期运行 generator 两次，因此 Python 生成逻辑、回调构造和字符串拼装都会重复。它需要第二次运行时已知全部槽数量，才能将动态区安全地放到静态区下方。

两遍的槽映射必须完全相同。实现不会缓存第一次的源码，也不会比较两次源码；不能在生成器里使用随机数、时钟、文件读取、计数副作用，或按 m.bound 生成不同的槽集合。m.bound 在预览和正式遍历中本来就不同，生成器可以通过公开动态基址 API 生成不同地址文本，但必须保持同一套槽名。

回调同样在生成阶段执行。一个处理单个帧字符的 consume 回调不会在 Python 中按实际帧长度调用 N 次；它返回一份 DSL 循环体，该循环在 PP3 执行时按帧长重复。

## 如何测量

要比较宏策略，可分别报告：

- 生成源码字符/字节数。
- Runtime handler 分派次数或 DSL 循环轮数。
- 运行时输入数值位数、元素个数、地址历史规模。
- 未启用 tracing 时的 wall-clock 及重复次数。
- Python/PP3 提交、操作系统和输入分布。

若 Runtime 使用 sys.settrace 统计 handler 分派，测量本身会改变实际耗时；分派数适合比较解释层工作规模，不是加速比。Toolkit 自身测试只验证功能和语义，不是性能基准。
